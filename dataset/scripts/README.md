## Why ERA5 and GPM are blocked

Both require a personal account (free, self-registration) and an API
key/password. Account creation and credential handling are left to you
deliberately — this assistant does not create accounts or hold passwords on
your behalf. To unblock:

1. **ERA5:** register at https://cds.climate.copernicus.eu, put your API key
   in `~/.cdsapirc` (format in `download_era5.py`'s docstring), accept the
   dataset licence once via the CDS website's download form, then
   `pip install cdsapi` and run `python dataset/scripts/download_era5.py --sample`.
2. **GPM IMERG:** register at https://urs.earthdata.nasa.gov, add a
   `urs.earthdata.nasa.gov` entry to `~/.netrc` (or run `earthaccess.login()`
   interactively once to save it), then `pip install earthaccess` and run
   `python dataset/scripts/download_gpm_imerg.py --sample`.

Neither package is installed yet (deferred until credentials exist, since
the scripts can't do anything without them).

Both scripts fail fast with a clear message (verified: ran each without
credentials, got the intended error, not a stack trace) rather than
silently doing nothing or prompting for a password.

## Conventions every script here follows

- Raw files are never modified in place; any cleaning happens in a separate
  `dataset/processed/<name>/` step (not yet written for any of these 3).
- Every script writes its own `*_manifest.json` (or `SOURCE.md`) recording
  exact source URL, parameters requested, license, and download timestamp.
- Checksums are verified against the source's own published checksum where
  one is published (Zenodo); ERA5/GPM don't publish per-file checksums, so
  those will instead get a post-download sanity check (timestamp/coordinate
  range, no all-NaN variables) once a sample is actually downloaded.
- No credentials are ever read from or written into this repo.
